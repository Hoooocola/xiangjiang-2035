## 运行与访问

```bash
pnpm install
pnpm dev
# http://localhost:3000/experience

# 生产演示
pnpm build
pnpm start --hostname 127.0.0.1 --port 3001
# http://127.0.0.1:3001/experience
```

本次交付时生产服务运行于 3001；停止进程或重启电脑后需重新启动。三维页面无需数据库、地图 token 或外部地图服务。原研究页面 `/create-research` 仍按 README 的数据库环境运行。

## 架构与选择

Next.js 16.3.4 / React 19 / TypeScript + Three.js 0.186.1。GeoJSON 离线生成，浏览器用局部米制坐标构建几何。自定义相机、材质和渲染生命周期，与 React UI、地点配置分离。选择 Three.js 是为了直接控制局部城市的风格、建筑边缘、雾、水面和摄影式镜头；当前不需要地球级流式瓦片。Cesium 与双引擎方案的比较见 `legacy-audit.md`。

## 数据真实性

真实：OSM 湘江主河道、洲岛内洞、建筑占地、道路/桥梁线位、公园轮廓。渲染 16,086 个建筑多边形，其中 1,041 个有 height/levels 标签；要素数与多边形数不同。

估算/艺术化：未知建筑高度、统一 1.65 高度视觉倍率、立面窗位、树木、桥墩、道路宽度、山体高程。未接入 DEM 或定制地标模型。鹅洲沿用明确标记的未校准演示坐标。铜官窑与昭山为范围参考点。没有虚构研究成果。

源 CRS 为 WGS84，局部坐标 1 单位=100m；不是 CGCS2000 精测成果。ODbL、数据请求清单和坐标公式见 `data-sources.md`。四个不完整支流关系已过滤，后续需要完整边界补充；湘江主河道完整保留。

## 实际验证及限制

生产构建成功；类型检查成功；Vitest 11 通过、26 个数据库集成测试按原配置跳过。本轮没有变更数据库逻辑，也没有声称完成数据库回归。ESLint 无错误，旧静态原型保留两处已有 unused-vars 警告。

浏览器实际操作和截图见 `visual-review.md`。已测试开场、巡游、拖动、滚轮、旋转按钮、镜头预设、日夜、概览、地点聚焦/返回。检查了主屏、旋转、局部与全段边界；修正过错误水面封口、桥面方向、山体进入水面、夜景过暗、标签靠边、焦点导致顶部裁切等问题。

本机内置浏览器生产版 1440×900，核心日间/夜间短时读数约56–59 FPS，全段约65–66 FPS；这些是现场采样，受屏幕刷新率与浏览器调度影响，不是跨设备基准。1920×1080 核心日间约53 FPS；390×844 桌面模拟视口约66 FPS，并非手机性能。详细 draw calls/三角形/资源数见 `performance.json`。没有进行 Safari 真机、移动设备 GPU、冷启动网络或长时堆内存剖析；不能承诺所有设备无卡顿或无泄漏。

## 距离最终品质的差距与下一轮优先级

1. **真实地形与数据补齐**：取得许可清晰的 DEM、完整支流水域、建筑高度与沿岸覆盖；校准鹅洲与研究边界，建立 CGCS2000 数据入口。
2. **地标和核心资产**：橘子洲南端、重要桥梁、东岸地标及山麓增加轻量 GLB、退台、铺装、岸线细部；增强长沙辨识度。
3. **光照与材质**：优化窗格混叠、岸线反射、夜景局部照明、树木变化与近景接触阴影。当前水面仅法线细波与高光。
4. **全段连续性**：目前完整的是河道，沿岸城市集中核心区域。远景较空，不以雾和标记冒充全段城市建设。
5. **性能工程**：用几何分块/Worker 或预生成二进制资产替代浏览器集中挤出；补 Safari、低端硬件、真实触摸及长时间内存测试。

本轮未新增完整研究数据库功能，重点工作集中在真实空间、镜头、三维表现与交互。
