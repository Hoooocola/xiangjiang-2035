# Masar Destination 参考研究

2026-10-20，本轮使用实际浏览器操作；来源：
- https://www.masardestination.com.sa/en/experience
- https://immersive-g.com/projects/masar-destination/

## 观察条件与限制
初次从窄侧栏打开时出现移动端 Start the Visit 和操作说明；随后调整桌面尺寸时页面停留开场，控制台有 dispatchEvent null 错误。以桌面视口重新加载并等待资源后，三维体验恢复，已实际操作日夜、拖动、滚轮、marker 和 Components。最初错误不能等同于站点长期不可用。首屏资源耗时明显，未记录可靠精确加载时长。视口工具对已打开标签未始终生效，最终 DOM 核验桌面为 1440×900；窄屏复测未成功，不声称完成移动端审计。

## 视觉系统（直接观察）
- 城市主轴占据画面，纵向透视和斜向横构图均出现；主区的立面网格、退台、树木及地面铺装细节显著丰富于外围。
- 日间为暖白底、灰石色城市，少量绿化和紫色交互强调。建筑并非简单单色盒体，立面节奏是完成度的重要来源。
- 核心外围持续存在大量低细节白模与道路。远处饱和度和对比度下降，逐渐融入背景，没有可见矩形底座。
- 夜间背景与外围转为墨青，核心建筑窗口和道路亮起；地形仍有层次。不是黑色遮罩。
- 联系光影与地面接触的暗部建立体积；是否用 SSAO、烘焙或自定义后期，仅凭画面无法确定。
- 透视缩短在画面上可见，倾向于透视相机；未读取源码验证投影类型。

## 相机（实测与未知）
- 初始位于城市轴线斜上方；开启后的镜头有自动运动，用户输入后可继续探索。
- 左键拖动主要表现为画面平移/沿城带移动，并非默认地球 Orbit；拖动后场景主体平滑偏移。
- 滚轮向上得到更近、更低的城市视角，建筑体积和立面更清晰。无法仅凭画面证明改变的是距离、FOV 或二者。
- 运动具有缓入缓出及停止缓冲；没有精确录屏测时，不将具体 easing 函数或时长冒充观测值。
- 未彻底测出全部边界；未验证模型旋转和相机旋转的内部区别；固定目标点、自动巡游轨迹的具体实现未知。

## 交互（实测）
- 初始说明包含拖动、滚轮、两指缩放；曾观察到 Start the Visit 按钮，但桌面恢复后自动进入场景，未完成按钮点击至结束的全链验证。
- 左下日夜开关可点击，主题变化涉及背景、外围、建筑和灯光。左下有长条小地图，右下两个菱形入口，右侧有指南针。
- marker 为小型菱形，指针经过时出现地点名；点击测试后视角发生变化，但没有稳定捕捉到独立地点信息卡，因此不声称已验证该信息面板。
- Components 点击后打开全屏分层菜单，场景缩远、变暗，文字列表与大标题浮于场景之上；保留返回入口。
- 控件多为 div/canvas，而非语义化按钮，辅助技术可访问性不能从画面确认。

## 对湘江的实现决策（独立设计，不是反向工程结论）
Three.js 透视相机，主拖动为平移、Shift/右键旋转；自定义阻尼和五次缓动路径。主轴改为真实湘江与橘子洲；以真实建筑占地和道路为约束构建浅石灰城市。远景雾随距离变化，范围外持续保留水道及基础地形；不采用截断沙盘。日夜分别改变材质、光照和水面。UI 采用开放布局、细线、少量文字与菱形 marker，不使用 Masar 商标、模型、贴图或源码。
