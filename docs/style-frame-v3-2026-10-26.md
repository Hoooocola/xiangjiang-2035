## 对照条件

- 固定目标 `[2, 0, -1]`，相机距离 58、方位角 0.38、极角 1.12、FOV 38°；场景单位为 100 米。
- 1440 × 900 逻辑画面，像素比 1.5，导出 2160 × 1350。
- 相同 GIS 数据、建筑高度、AOI 权重、树木与地形；几何只构建一次，切换材质引用。
- 构建统计：158242 栋建筑，1331 栋具有已知高度，42023 棵树，221 个参与材质切换的网格。该统计为加载场景总数，不是镜头内数量。
- 四张均冻结水面时间，禁用相机操作，去除标签、界面和 CSS 渐变遮罩。当前帧为当前材质和灯光的纯场景输出，与体验页带 UI 的截图不能逐像素等同。
- 沿用原有色调映射、输出色彩空间、阴影、Bloom 链和雾距离。V3 更换角色材质、光色、环境色与光强；日夜曝光分别保持 1 / 1.05。

## 候选方向

日间采用中性略暖背景、低饱和暖灰地面和立面、冷青灰屋顶，水体保持青绿，植被保留绿色。初版地面偏沙色，已降低黄色成分，并加深冷色屋顶以区分材料。

夜间把原来的偏蓝环境改为低饱和石墨青绿，主体采用暖中性立面与低强度材质自发光，地面亮度低于建筑；窗灯覆盖率降低并提前淡出未解析的细窗，避免密集噪点。地面初版偏褐，已减弱暖色和自发光。桥灯沿用原有结构并降低强度。

这属于 B 路线：没有增加实时反射、点光源、贴图资源或后处理通道；没有采用 C。这里的材质自发光是艺术补光，不会像真实光源一样照亮周围物体。

## 验证与观察

- 四个状态都在浏览器实际渲染并导出；最终页面控制台无错误。开发中发现并修复了实例法线局部变量与 Three.js 着色器变量重名的问题。
- 切换日夜和 V3 后返回当前日间，再次导出 PNG 与首次基准文件逐字节一致。
- 夜间关闭窗灯、桥灯与 Bloom 后，建筑体量仍然可读。两张夜景图的全图 RGB 平均绝对差约 0.087 / 255，说明这个固定距离主要由体量与材质支撑，而不是窗灯；这不代表近景灯光效果已经验收。
- `pnpm typecheck` 通过。
- `pnpm test`：64 通过、26 数据库集成测试跳过。
- `pnpm lint`：0 错误；原 `prototype-html/js/app.js` 中 2 个已有未使用变量警告。

当前局限：体块模型与估算高度保持原样；建筑材料仍以角色分工为主，缺少真实逐栋立面差异；水面没有真实城市倒影；尚未验证自由镜头下的近景窗灯、远景衰减和移动性能。现有体验页没有接入这一套新材质。

## 验收后再推进

先判断日间暖灰与冷青灰的比例、夜间主体与背景的分离、水色，以及是否需要更多局部而非整体的暖光。此组通过后，才检查宏观 / 研究 / 地点三个尺度；再决定是否推广全段。

实现入口：`app/experience/style-frame/`、`src/experience/style-frame/`。原灯光模块仅额外返回 hemi 与 fill 引用供实验页使用，本轮未修改体验页的灯光参数。
