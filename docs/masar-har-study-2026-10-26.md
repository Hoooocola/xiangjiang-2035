# MASAR HAR 学习与湘江第一阶段调整

日期：2026-10-26。依据：用户提供的 `www.masardestination.com.sa.har`（111 个请求）。分析的是该次抓包的前端产物，不代表网站最新源码，也不是服务端代码。

## 已确认的机制

| 证据（HAR 内资源 / 类或方法） | 确认结果 | 对湘江的启发 |
| --- | --- | --- |
| `build/js/app-v2/644.js` / CustomCityMaterialsPlugin | 按墙、屋顶、地面、道路、树、玻璃、外围建筑等材质名分组，具备 day/night/wireframe 及组件配置 | 先划分场景角色，再调曝光和辉光 |
| `ao.jpg`、`light.jpg`、`ground-areas.png`、`ground-tiles.png` / wallMaterialOverride、groundMaterialOverride | 实际采样 AO、灯光和地面分区贴图；区域颜色可独立映射，墙面光照包含方向和高度相关逻辑 | 光亮感依赖预制信息和分区材质；不能靠满屏程序窗灯替代。仅能确认加载和采样，无法据此确认完整离线烘焙流程 |
| 同一脚本 / outsideMaterialOverride | 外围独立材质、距离退隐和昼夜处理 | 主体和背景共享地理位置，但不共享视觉强度 |
| `city.glb` JSON、ComponentsPlugin | 模型中有单独命名的步行空间、下穿空间、道路、公交对象；组件着色器用 UV 边缘生成边线 | 参考图中立体结构不是普通地图矩形边界，也不是全模型三角网线 |
| 页面 setComponents、BuildingsPlugin.hide | 切换组件会切材质、组件、热点相机；部分状态将 Buildings 节点 visible 设为 false | 研究阅读需要完整状态变化，而非只给当前图形加亮 |
| HotspotsPlugin.goToName、GLB 节点 | 使用命名的相机位置和注视点，并有桌面/移动端变体 | 精细叙事需要按对象设计镜头；不能只用统一距离 |
| CompositionPlugin 的片段着色器 | 包含 FXAA；glowIntensity 参数存在，但该着色器辉光采样循环被注释、初始累积色为零 | 不能把参数名或打包依赖当成正在运行 Bloom 的证据；此证据不排除网站其他光效 |

GLB 元数据标明 Blender glTF 导出器，包含 934 个节点、102 个 mesh。未把对标脚本、贴图、模型加入产品；仅在临时目录静态分析，不执行下载脚本。本次实现独立编写。

## 本阶段落地

- 保留原有 Three.js、地理数据、连续沿江 AOI、自由相机、现有后处理与六类资料功能。
- 日间加深主体地块、分开屋顶与地面色阶；外围保持低饱和浅色。
- 夜间增加连续地块和建筑体量的低频亮度，减少随机窗灯密度与亮度、远景窗灯细节和桥灯强度。水面保持独立色调。
- 仅在存在“当前可见且被选中”的研究对象时，平滑降低底图亮度/饱和度；关掉相关图层可退出此效果。研究图形不参与底图压低处理。
- 研究边线从强 HDR 放光改为保留图层色的细线；面的内部细分后贴合地形，边线与填充统一到地形上方 4 米，避免原来的 19/14 米高差。该高度是渲染避让，不是实测高度。
- 点标记底座从 22 米改为 4 米，顶端从总高 92 米改为 16 米，并缩小几何体；HTML 锚点继续与顶端共享定义。
- “在地图中查看 / 定位关联空间”定位可见的已选资料对象，并保留资料面板，不再无条件跳回整个地点。
- 研究对象选中时隐藏普通地点标记，避免地点标签和资料标签竞争；退出研究选择后恢复。

## 验证与边界

64 个测试通过，26 个数据库测试跳过（未运行数据库集成环境）。新增回归检查验证非平面地形上研究面内部与边线的统一离地高度；已有测试覆盖点标记与 HTML 锚点一致性、投影与图层交互。TypeScript 检查通过。ESLint 无错误，原 prototype-html/js/app.js 保留 2 条未使用变量警告。

本地浏览器检查日/夜核心视图、生态资料选择及定位按钮；未发现 WebGL 着色器错误。截图用于本阶段验收，不是与对标站像素级匹配的证明。预览端口为 3002。
