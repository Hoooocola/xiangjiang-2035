## 研究流程与资源

两轮鹅洲六步 + 两轮矿坑七步实际浏览器验证：

- 初始地图没有请求研究 JSON；鹅洲进入时不请求 quarry.json。
- 图可达性 8/4 → 删除连接 7/5 → 恢复 8/4。对象可在场景热点或选择器查询，重叠热点有列表入口。
- 自由模式、日夜、用户拖动打断运镜、退出返回精确原视角通过。鹅洲始终使用同一个 canvas。
- 鹅洲退出后两轮均回到 222 geometries / 16 textures，原建筑/树木统计恢复一致。相对原 V3.1 减少的12个粗体量/479棵树来自内陆水体过滤修复，原始数据不删改，也不是为提升 FPS 调低预算。
- 矿坑东西/南北剖面不同，阈值 10°/70° 产生不同交叠长度；35° 只作演示。两轮结束保持 27 geometries / 3 textures。
- JS heap 主图两轮退出采样约 167.0 / 176.1 MiB；矿坑分析约 18.9 / 20.4 MiB。GC 非固定时刻，不能据此宣称消除全部内存泄漏；GPU 计数回归是明确验证项。

## 数据运载

- 四个原始核心 JSON：22,310,269 bytes；spatial 目录 12,154,467 bytes；加内陆水体/研究资产后 public/data 共 34,663,293 bytes。这是磁盘清单，不是首屏传输量；WorldCover 同目录中有 JSON/BIN/TIF，不是全部默认下载。
- V3.1 云端实际已使用 Brotli，四文件合计 encoded body **4,930,567 bytes**，不是理论 3MB。cold transferred 合计 4,931,767 bytes；浏览器 warm 重新验证四次，各 transferSize=300。
- V3.1 baseline 首屏可操作 cold 10.392s / warm 4.243s，受网络影响。各文件响应/资源计时见 transfer-baseline.json。
- 本轮对摘要版本 URL 增加浏览器长缓存。**V4 云端命中/传输需在 Preview 生成后实测，在 PR 追加，不预先宣称收益。**
- 森林数组 163,840 项：JSON 原始327,681 bytes、本地 Brotli6,024；uint8压缩4,792；bitset压缩4,168。收益仅约1–2KB压缩，不值得改传输契约，因此不实施二进制新格式。只将运行时数组改 Uint8Array，原分类/空间精度不变。
- JSON 解析本地 median：主几何34.68ms / 环境22.01ms / context18.74ms / terrain2.76ms，不含下载/解压，不将本地理论 Brotli 体积当作云端传输。
