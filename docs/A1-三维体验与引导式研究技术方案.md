## 3. 建议实施方案

### 3.1 Scene Focus：复用几何和现有聚焦器

沿用 `focusSpatialInformation(id, options)` / 当前引擎的单一 `CameraRig`，补足统一入口语义（建议接口名 `focusSpatialFeature(featureId, options)`，最终名称由负责人确认）。选中动作只消费已经存在的空间几何和资产绑定：

- Point：保留地点/对象 Marker，以地形锚点和微弱基座环作为焦点。不生成推测范围。
- Line：以源路径几何描边或叠加窄带强调方向和长度；禁止将其改成矩形范围。
- Area：使用已登记 Polygon / MultiPolygon 的真实边界，材质轻度提亮或边界描线；不以包围盒代替面。
- 3D Object：优先从 `sourceFeatureIds` 映射到已加载的真实场景对象，提升该对象边缘/表面明度；无可靠映射时退回锚点，而非复制/挪动模型。

目标对比通过现有 `terrain.importance`、AOI 连续权重和目标对象局部描边表达。背景降低饱和度/对比度、非目标标注淡化，但保留河流、近岸、远岸建筑的可辨关系；避免全屏遮罩、硬裁切和将未选 Marker 全部隐藏。焦点视觉与数据信息来源保持独立，昼夜两个主题采用同一权重参数映射。

### 3.2 Camera Focus Controller：同一动画所有权

不新增并行相机管理器。扩展 `CameraRig` 与 `engine.ts` 现有聚焦方法：

1. 从对象实际顶点/注册范围计算中心与取景距离；按对象形态选构图，必要时使用当前视向并做小幅方位修正。
2. 复用现有 easing、距离约束、`minimumCameraY`、河廊相机边界和减少动态效果支持。动画期间只有 CameraRig 可写相机姿态。
3. 新的 focus/tour 请求取消上一条 transition/route；pointer、wheel、键盘以及重置/退出立即调用同一 stop/cancel 路径。用户接管后不自动续播或夺回镜头。
4. 记录进入聚焦前的 `CameraPose`，提供显式“返回原视角”；只有该聚焦上下文还有效时恢复，重置/切地点时清理。
5. 默认不自动环绕。可选 Cinematic View 在用户主动启动时播放一次短小、限幅、目标可见的水平视差路线；用户任何操作、退出功能和隐藏页面均停止。设置遵循减少动态效果，提供关闭开关。

### 3.3 StoryMap：显式模式 + 可逆进度

新增纯状态协调层，UI 和镜头读取同一进度值：

`explore → placeSelected → guided(active, progress ∈ [0,1]) → exiting → explore`

进入 `guided` 必须由用户点击“开始引导式研究”。普通模式保持原生地图滚轮缩放；StoryMap 只在已激活的叙事容器捕获 wheel/touch 输入，不允许地图缩放和故事相机同时响应。退出、换地点、进入其它页面或用户拖动接管时结束/暂停叙事并归还相机控制。

建议 6 个章节（五个区间、章节边界明确，进度连续可逆）：

| 序号 | 章节 | 显示规则 |
|---|---|---|
| 0 | Place | 地点名称、已核验的位置与现状说明 |
| 1 | Context | 地形、湘江、两岸城市；只切换现有场景层 |
| 2 | Resources | 现有生态/地理/文化/社会对象及其来源和精度 |
| 3 | Evidence | 与 placeId / featureId 关联的资料、证据、图层 |
| 4 | Findings | 只呈现已有、可追溯研究发现；没有时展示“研究问题/数据缺口” |
| 5 | Opportunity / Proposal | 仅呈现登记的机会或标有 DEMO 的概念方案 |

关键帧建议保持数据驱动，每帧包含 `cameraPose`、`target/heading/pitch/range`、`activeFeatureIds`、`visibleLayers`、`informationRecordIds`；研究章节数据与相机插值代码分离。摄像机姿态沿用 `CameraPose`（target、distance、azimuth、polar），不再复制一套坐标系。滚动输入经 deltaMode 归一化与有限速率累积成 progress，由 progress 插值关键帧；不按 wheel 事件逐次触发完整动画，因此反向滚动自然回放。文本和图层也直接按同一 progress 的区间/阈值计算显隐。停止滚动即停止更新，避免自动补完；触控板惯性只改变进度，不产生不可逆动作。

首个洋湖样板通过 `SceneDefinition` / `ChapterDefinition` 适配器提供章节内容和 feature/record ID。Mock adapter 与正式 Atlas adapter 实现同一只读接口，DEMO 状态随数据保留；不在相机/动画逻辑里写地点真实研究内容。章节缺资料时显式输出空状态/问题线索。

### 3.4 UI：空间锚点、编辑式叙事、按需详情

仅限正式地图地点介绍、Field Notes、Scene Focus、Guided Research 区域。点击地点先给轻量空间锚点（地点名、类型、1 句解释、DEMO/来源提示和“开始引导式研究”入口）；侧边用无卡片式层级文字显示章节标题/短叙述/章节计数。长正文、来源、精度、证据列表仅由“研究详情”打开现有详情视图。保留紫色只做少量当前焦点/进度强调，使用既有 CSS 变量和信息排版规则。课程成果展示页面不改。

### 3.5 粒子与雾：低成本、最后接入

- 粒子用单一 `THREE.Points` + BufferGeometry / ShaderMaterial 批量绘制，限制数量和 DPR，慢速低亮度；在相机近裁剪面之后、主要文字安全区域之外布点。基于时间/哈希移动，不做每粒子 DOM 或闪烁；标签/信息层始终盖在粒子之上。页面隐藏时暂停，减少动态效果或性能降级时关闭。
- 现有 `createEnvironment` 已使用随昼夜混合的 `THREE.Fog`。优先在现有 fog color/near/far、背景渐变和现有色调映射上小幅调参验证；远近层次由距离雾呈现，不改每栋建筑材质。不建议第一轮真实体积云或新增后处理 pass。
- 保留开关和逐步降级路径：粒子关 → 降低点数/DPR → 仅保留现有距离雾。以现有 renderer.info 和帧率遥测记录基线及开启效果的差值，再决定是否进入产品。

## 4. 数据开发协作接口建议

使用现有 `MapObject` / `InformationFeature`、`AtlasRecord` 和注册器，不建立第二套 GIS/研究实体。引导内容层只需要只读适配器：

```ts
interface ResearchSceneAdapter {
  getPlace(placeId: string): Promise<PlaceNarrative | null>;
  getFeature(featureId: string): Promise<InformationFeature | null>;
  getLayer(layerId: LayerId): Promise<InformationFeature[]>;
  getRecord(recordId: string): Promise<AtlasRecord | null>;
  getRelated(placeId: string, featureIds: string[]): Promise<{
    analysisIds: string[];
    evidenceRecordIds: string[];
    questionRecordIds: string[];
    opportunityRecordIds: string[];
  }>;
}
```

查询键固定为 `placeId` / `featureId` / `layerId` / `analysisId`。当前 Atlas 如暂时没有 analysis 实体，`analysisIds` 只能通过可选的兼容能力/空结果表达，不在 UI 动画中推断分析结果。适配器输出原始 ID、几何、来源、精度、dataStatus；镜头层只读取这些信息，不写回或变换数据几何。实施前请 B 方确认 analysis/evidence/research-question 的已有命名和字段，避免平行接口。拒绝缺来源、精度或状态的正式研究展示数据；Demo 必须保留显式标记。

## 8. 与当前代码对应的 A2 执行范围
