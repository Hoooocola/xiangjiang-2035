## 鹅洲网格与水位

离线脚本 `scripts/story/prepare-relative-grid.mjs` 从本项目已授权衍生 GLB 读取解码顶点，转换到既有局部米制坐标，以 10m 网格、真实岛界掩膜取单元最低顶点。无顶点单元用最近有值单元补齐；元数据保留填补数量、源文件 SHA-256、模型相对零点和方法。

原始模型最低包络的第五百分位作为相对零点，数值记录于 `modelZeroMeters`。这不是海拔、裸地 DEM/DTM 或水文站水位。建筑、扫描孔洞和重建噪声均可能影响结果；归一化不提升精度。

预设相对水位 8.5 / 10.5 / 12.5m，警惕余量 1.2m。算法由岛界相邻外部水体的低地网格种子出发执行四邻接 BFS，仅连通且高度不高于水位者为淹没区。水位+余量再次连通筛选形成警惕范围；未连通但高度偏低的凹地也标警惕，不伪称安全。其他为相对稳定区，绝不等于绝对安全。

`counts × cell²` 汇总面积；点落网格得到代表点与设施分区。动画只插值水面与边界透明度，BFS 和统计仅输入改变时执行；动画期间 UI 注明数字是目标情景。地形遮挡水面，使上升过程可见。没有水动力、流速、淹没深度可靠性或真实重现期。

## 道路、设施与四种组织

来自既有 `ezhou.json` 的 OSM 道路线顶点构成图，8m 以内节点归并，每段平面米制长度为边权。Dijkstra 求候选设施—聚落及桥外方向最短路径；代表点/设施与图节点的接线距离需在 150m DEMO 假设内。图连通不代表合法通行、车辆条件或汛期可通行。

12 个模拟聚落、66 个服务单元、3 个活动节点直接沿用 `ezhou-study.json`，不冒充实际人口、房屋或游客统计。每点保留既有不同属性与道路关联。

- A：两个候选设施收集与拟议桥外纳管方向；接入点/容量/跨桥条件待核实。
- B：北段与中段密闭收集、暂存和外运，图中蓝色为收运道路。最终接收处理另列待核实，管网长度为零不代表没有收集设备。
- C：南段与中段局部处理，加运维道路。污水后续用途/处置、污泥、环保和用地条件未知，无向江排放线。
- D：按当前代表点分区应用固定规则：淹没→中段密闭；警惕→北段拟议纳管；稳定→南段局部处理。规则透明，不预设最优。

统计用唯一道路边与唯一接线段去重计算管网长度，唯一运输道路边计算收运/运维长度；收运道路按5m间距与模拟淹没单元求交叠。OSM 桥段高度未知，不用岛上网格推断桥梁被淹。受淹设施由候选点分类计算。点击“中断桥段”移除一段边重新计算，并不保证所有替代桥段也阻断。

几何覆盖、满足的模拟条件、未满足条件与缺少现实数据的条件分别输出。未编造成本、处理效率、排放合规或减排收益。

## 矿坑

地形、高程、坡度复用 `src/place-research/analysis.ts` 的 `quarryHeight` 与 `slopeDegrees`。V4.2 9幕剖面复用每幕161个5m采样；默认单幕，局部窄带实体剖切，可切9幕阵列。幕底−20m只是图解支撑，不是地下/水下地形。曲线与幕使用同一采样。

岩壁与生态区复用 V4.2 非圆形多边形，程序枝叶森林与实例化/LOD；面积和冠幅为模型估计，不是植被调查或修复成效。

两套 DEMO 路径共用入口和活动目标，各自固定不同折点。每2m样段采样地形高程，三维长为 `sqrt(平面长²+高差²)`。中点坡度落入用户当前闭区间则计坡度交叠；中点在同一生态多边形则计生态交叠。相邻命中样段合并为连续高亮结构。水面交叠另列未满足条件。

入口联系复用既有 DEMO 道路图 `accessRoute`；中断入口接线会实际失去图可达性。没有现实道路坐标支持，因此不宣称真实路径、实际车程、真实入口或安全路线。比较不预设B优于A。

## 研究记录

导出包含 schema、记录时间、场地、所有输入参数、数据状态、四情景或两路径实际计算结果、网格源 SHA、满足/未满足/未知条件和方法限制。记录时间只是保存时间，不是研究数据年份。恢复时校验参数并重新计算。

收运长度包含密闭收运聚落的入户支路、接线及设施至桥外的道路并集；不是仅计算桥外干线，也不是最优车辆巡回行程。相同段只计一次，不推断班次、车辆需求或实际时间。

云端构建沿用仓库 `.vercelignore`；本轮仅为测试所需的 `docs/v2.6/import-report.json` 添加例外，其他离线文档仍排除。此文件是现有课程元数据，不是新增课程成果。
同一候选位置在不同情景中的拟议用途由 `facilityRoles` 显式配置：A 为收集转输，B 为密闭暂存，C 为两个局部处理单元，D 使用原有收集、处理、暂存分工。这些是互斥的 DEMO 假设，不是已经存在的设施。
